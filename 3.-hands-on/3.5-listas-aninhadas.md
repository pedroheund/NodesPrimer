# 3.5 Listas aninhadas

### A caixa dentro da caixa

Se uma lista já é como uma caixa com vários itens organizados, uma lista aninhada é como uma caixa que, em vez de guardar só objetos soltos, guarda também outras caixas lá dentro.&#x20;

Imagine uma caixa maior com três caixas menores dentro dela:

* uma caixa com lápis;
* uma caixa com canetas;
* uma caixa com borrachas.

A caixa maior organiza os grupos. Já cada caixa menor organiza os itens de cada grupo.

No Nodes, isso é o que chamamos de lista aninhada: uma lista que contém outras listas.

***

### Um exemplo simples

Se uma lista comum poderia ser assim:

`[lápis, borracha, caneta]`

uma lista aninhada seria algo como:

`[[lápis, caneta], [borracha, apontador], [régua]]`

Aqui, não temos apenas uma sequência única de itens. Temos grupos de itens.

* O primeiro grupo tem lápis e caneta;
* o segundo grupo tem borracha e apontador;
* o terceiro grupo tem régua.

Ou seja: existe uma lista principal, e dentro dela existem listas menores.

***

### Por que isso existe?

Listas aninhadas servem para organizar dados que fazem mais sentido em grupos, e não tudo misturado.

Pense assim: uma lista comum é uma única caixa com tudo junto, já uma lista aninhada é uma estante com várias caixas separadas.

Isso é útil quando você quer manter uma organização mais clara entre os elementos.

Por exemplo:

* elementos separados por pavimento
* barras separadas por elemento
* pontos agrupados por poligono

Em vez de colocar tudo em uma lista só, você mantém a estrutura dos grupos.

<figure><img src="../.gitbook/assets/image (25).png" alt=""><figcaption></figcaption></figure>

Você não precisa pensar em programação logo de início. Basta pensar em organização.

Quando fizer sentido separar os dados em grupos, provavelmente você está lidando com uma lista aninhada.

***

### Na prática, o que muda?

Numa lista comum, você pega um item diretamente.

Numa lista aninhada, primeiro você escolhe qual caixa quer abrir, e depois escolhe qual item daquela caixa quer pegar.

É como dizer:

* quero a segunda caixa;
* e dentro dela, quero o primeiro item.

Então a ideia principal é essa: em listas aninhadas, existe mais de um nível de organização.

<figure><img src="../.gitbook/assets/image (27).png" alt=""><figcaption></figcaption></figure>

***

### Quando isso é útil no Nodes?

No Nodes, listas são muito usadas para agrupar e manipular dados, acessar itens, contar elementos, ordenar ou aplicar operações sobre conjuntos inteiros.&#x20;

As listas aninhadas entram quando você não quer apenas vários itens, mas sim vários conjuntos de itens.

Elas são úteis quando a rotina precisa preservar agrupamentos.

Por exemplo:

* um grupo de elementos para cada pavimento;
* uma sequência de pontos para cada forma;
* uma lista de resultados para cada barra;
* vários conjuntos de dados dentro de uma mesma estrutura.

Nesses casos, a lista aninhada ajuda a manter o fluxo mais organizado e o resultado mais fácil de entender.

***

### Resumindo

Listas aninhadas são listas que guardam outras listas dentro delas.

Elas servem para organizar dados em grupos, mantendo uma estrutura mais clara dentro do fluxo. Em vez de juntar tudo em uma única sequência, você separa os elementos de uma forma que faça sentido para o problema que está resolvendo.

No fim, é só uma maneira de organizar melhor:\
primeiro as caixas, depois o que tem dentro delas.
